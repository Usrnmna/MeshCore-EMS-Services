WINDOWS 10 X64: START THE CONTINUOUS SERVICE

Version 0.9.5 - Beta (v0.9.5-beta)

Double-click Start-Service.exe once.

The launcher starts the local MQTT broker and MeshCore channel responder using
this folder's existing run.ps1 and config.json. If the local Python environment
is missing, the existing setup routine creates it (Python must be installed).

With serial_port: "auto", the service detects the single attached USB serial
device at each start, even when its COM number changes. Leave the console open;
the service listens and responds on assigned channels (default #autatestbot).
Ctrl+C stops it. Run only one instance for the selected node.

Keep Start-Service.exe in this folder with the other files. An optional desktop
shortcut can reference this executable. No administrator permission or activation command is needed.
This does not register a Windows boot service. If no USB device or multiple
candidates are found, startup reports an error. Set serial_port to the intended
fixed COM device when several USB serial devices are used.

Optional diagnostics:
    Start-Service.exe --check
    Start-Service.exe --ports

The executable's source is Start-Service.cs. It launches the PowerShell entry point.
Configuration is in config.json; command programs are in scripts/.
Run verify.cmd after setup to run the tests in tests/.

AQI: Set AIRNOW_API_KEY in the launching environment (see README), then send
!aqi LATITUDE LONGITUDE or !aqi LATITUDE, LONGITUDE on #autatestbot.

See README.md for all commands, including traffic, rivers, UV, heat advisories, lightning potential, flood warnings,
flood alarms, and snowpack. Restart the service after changing config.json.

See MULTI_CHANNEL_GUIDE.md to add Public, hashtag, or private channels, assign
programs to them, manage private keys and MQTT export, and use channel_setup.py.
Stop the bridge before channel setup; restart after configuration changes.

RADIO CONNECTION
USB serial remains the default. To use TCP, set config.json's connection to:
    {"type": "tcp", "host": "192.168.1.50", "port": 5000}
For BLE, pair in the OS first and set connection to:
    {"type": "ble", "address": "AA:BB:CC:DD:EE:FF"}
These are values for the connection object, not complete config files.
See README.md for firmware, Bluetooth access, timeout, and service-account details.
USB detection settings apply only when connection.type is serial.

FUNCTION_REFERENCE.md explains every maintained service Python function.

SHARED REPLY TIMEZONE
All MeshCore reply timestamps use responder.timezone in the active config.json:
    "timezone": "America/Los_Angeles"
Edit this one IANA zone and restart. Pacific time is the default (PST/PDT).
Installer upgrades preserve it. All programs receive MESHCORE_TIMEZONE.
See README.md for provider-text limits and standalone usage.

LOCAL GIS COMMANDS
The current source includes 28 commands. Local GIS examples:
    !trail Bear Creek
    !rec near 37.90 -122.20
    !peak Wildcat Peak
    !park Pleasanton Ridge
    !boundary 37.90 -122.20
    !boundary trail Bear Creek
Use NAME ATTRIBUTE for a focused field, such as !trail Bear Creek dogs.
Use NAME info for the full summary; NAME alone lists available subcommands.
Use ATTRIBUTE near LATITUDE LONGITUDE [MILES] for focused proximity queries.
Without miles, only the closest qualifying feature is returned. With miles,
results within that radius are listed; the explicit maximum is 25 miles.
Policy/amenity filters run before distance ranking. No API key or network
is required. These snapshots do not report live conditions or access permission.

gis_settings.json controls the data path, search radius, result limits, and
projection. The default path is ../data/ebmud relative to that settings file.
Older default_radius_miles settings are ignored; no radius is assumed.
!boundary also supports parks, watersheds, reservoirs, and recreation categories
before coordinates, near coordinates, or trail NAME. Send !COMMAND help for syntax.
Keep sources.json and all referenced GeoJSON files together at that location.
Standalone service ZIPs require the shared data directory separately.
Install the current requirements.txt with this service's Python interpreter.
See README.md, section Local GIS commands, for syntax, settings, diagnostics,
and tests. See ../data/ebmud/README.md for manual refresh and polygon repair.

The October 11, 2026 installers and service ZIPs include the GIS subcommands.
Installers include the shared datasets; service ZIPs require data/ebmud separately.
Upgrades preserve command definitions; review older registrations and explicitly
assign newly added commands to permitted channels.
Each GIS command has its own scripts/trail.py, rec.py, peak.py, park.py, or
boundary.py program; run it directly with a name or coordinates. All accept
--settings PATH. The three gis_*.py modules provide reusable implementation.
The dedicated scripts/floodalarm.py supplies JSON to the existing alarm monitor;
standalone execution does not create a subscription.
Updating an older installation requires responder.py, these command programs and GIS helpers,
settings, dependencies, data, and five command registrations with explicit
channel assignments. See ../INSTALL.md, section GIS source deployment.

Wildfire: try !firezone Truckee, !fires CAZ272, or !firewx CAZ272.
See WILDFIRE_GUIDE.md for sources, cache refresh, interstate coverage, and
!firealarm on/status/off. New commands require channel assignment on upgrades.

Point wildfire lookups: !smoke LOCATION and !firedanger LOCATION accept ZIP,
city/state, or latitude/longitude. Smoke replies begin with Smoke: and omit
location, Monitor: and PM10: lines. ERC uses local historical percentiles;
detailed fuel moisture requires optional FEMS access. See WILDFIRE_GUIDE.md.

California and Nevada landslide commands: !slidewarn LOCATION, !slidealarm on LOCATION
(status/off controls), and !slideinfo LOCATION. Locations accept ZIP, city, or GPS.
See LANDSLIDE_GUIDE.md. New commands require channel assignments on registry upgrades.
